# 输出目录与数据契约（A/A1）

本文是 `A/A1/config/paths.py` 与各阶段产物契约的速查表；新增主题（A2/B1…）可照此设计。

## 1. 两个根

| 根 | 默认路径 | 生命周期 | 是否纳入 git |
|---|---|---|---|
| 流水线数据根 | `A/A1/data/` | 大、可再生、跨轮累积 | 默认忽略；可按白名单只跟踪根级 CSV |
| 入库报告根 | `A/A1/reports/db_load/` | 小、需审计、按运行增长 | 默认忽略；需要时归档到外部 |
| 旧产物根 | `A/A1/techfin_common_output/` | 只读保留，新代码不写入 | 忽略 |

路径解析优先级：命令行覆盖 > `topic_config` 配置 > 默认值；相对路径锚定**主题目录**，
不是当前工作目录。所有脚本统一走 `config/paths.py`，不要各自拼路径：

```python
from paths import pipeline_root, load_report_root
from paths import new_pipeline_run, new_load_run
from paths import finish_run_manifest
```

## 2. 运行目录

- 命名：`YYYY.M.D-N`（月/日不补零，N 为当天第 N 次）；永远新建下一个序号。
- 每个运行目录写 `_run.json`：
  - `stage / script / script_sha256 / argv`
  - `started_at / finished_at / status`
  - `data_root / report_root / hostname / python`
  - `inputs / outputs`（路径 + SHA-256 + CSV 行数）
  - `counts / warnings / errors`
- ⑦ 入库报告根使用**独立序号**，不与爬虫运行目录混放。

## 3. 阶段产物

| 阶段 | 主要产物 | 关键字段 |
|---|---|---|
| ① 搜索 | `data/tech_fin_news.csv`、`<run>/search_*`、`coverage_report.json` | `article_id/title/url/date/level3_code/region_code/indicators` |
| ① 官方 | `data/techfin_official.csv`、`<run>/official_*`、`data/official_progress.csv` | `article_id/title/url/date/keyword` |
| ② 抓取 | `data/body_cache/<aid[:2]>/<aid>.json` + `.txt`、`<run>/body_index.csv` | `status/body_text/attachments[].path_rel/text_rel` |
| ⑤ OCR | 回写 `body_cache` 的附件 `.txt`、`<run>/ocr_index.csv` | `ocr_avg_conf/ocr_page_conf/ocr_low_conf_pages/ocr_truncated` |
| ④ 清洗 | `data/curated_corpus.csv`、`curated_uncertain.csv`、`curated_dropped.csv` | `level3_code/indicator_codes_all/region_from/region_confidence/quality_grade/event_group_id/near_dup_*` |
| ③ 抽取 | `data/techfin_a101_points.csv`、`<run>/points_delta.csv`、`points_resolved.csv`、`points_dropped.csv`、`extraction_report.md` | `point_id/level3_code/region_from/aggregation_type/year_confidence/evidence_verified` |
| ⑥ 评估 | `data/eval/` | `label_precision.csv`、`eval_report.md`、`coverage_history.csv` |
| ⑦ 入库 | `reports/db_load/<run>/` | `load_log/load_report.md/load_errors.csv/load_manifest.json/_run.json` |

## 4. 关键语义

- `level3_code` 是 join 键；中文名只是显示名。
- `region_from`：`text/title/summary/body/scope_city/scope_province/scope_national/aggregate/query/none`。
  loader 默认拒绝县级目标上的 `query/none/scope_national`。
- `aggregation_type`：`total/subset/breakdown/aggregate`。只有 `total` 参与主值；
  `breakdown/subset` 保留证据，loader 默认拒绝。
- `stat_year_src` + `year_confidence`：`period/text/relative/llm/window/doc`；
  `year_confidence < 0.5` 不产主值，loader 默认拒绝。
- `evidence_verified`：LLM 点的证据片段能否在正文/附件中定位；`0` 默认拒绝。
- 金额/数量单位不做跨单位换算；`value_text` 保留原文。

## 5. 旧数据

- 不自动迁移、不自动读写旧根；旧目录只读保留。
- 需要旧数据时：`--input-dir techfin_common_output/<run>`（loader）或
  `--output-dir techfin_common_output`（显式切换，会在旧根继续累积，通常不建议）。
- 新数据根从零开始累积；切换根后不会自动搬移累积库与正文缓存。
