# 输出目录与数据契约（A/A1、A/A2、A/A3、B/B1～B/B4、C/C1～C/C3）

本文是 `A/A1`、`A/A2`、`A/A3`、`B/B1`～`B/B4`、`C/C1`～`C/C3` 的 `config/paths.py` 与各阶段产物契约的速查表；新增主题可照此设计。

## 1. 两个根

| 根 | 默认路径 | 生命周期 | 是否纳入 git |
|---|---|---|---|
| 流水线数据根 | `A/A1/data/`、`A/A2/data/`、`A/A3/data/`、`B/B1`～`B/B4`、`C/C1`～`C/C3` 各自 `data/` | 大、可再生、跨轮累积 | 默认忽略；可按白名单只跟踪根级 CSV |
| 入库报告根 | 各主题 `reports/db_load/` | 小、需审计、按运行增长 | 默认忽略；需要时归档到外部 |
| 旧产物根 | `A/A1/techfin_common_output/` | 只读保留，新代码不写入 | 忽略 |

各主题目录共享仓库根的 `crawler_common.py` 与 `db/`，**不共享数据根**：各自的 `data/`、
`reports/db_load/`、运行目录序号互相独立。B/B1～B/B4 与 C/C1～C/C3 的代码与 A/A1 同源，
只替换了 `config/topic_config.py`、`config/extract_config.py`、测试与 README。

路径解析优先级：命令行覆盖 > `topic_config` 配置 > 默认值；相对路径锚定**主题目录**，
不是当前工作目录。所有脚本统一走 `config/paths.py`，不要各自拼路径：

```python
from paths import pipeline_root, load_report_root
from paths import new_pipeline_run, new_load_run
from paths import finish_run_manifest
```

## 2. 运行目录

- 命名：`YYYY.M.D-N`（月/日不补零，N 为当天第 N 次）；永远新建下一个序号。
- 每个运行目录写 `_run.json`：
  - `stage / script / script_sha256 / argv`
  - `started_at / finished_at / status`
  - `data_root / report_root / hostname / python`
  - `inputs / outputs`（路径 + SHA-256 + CSV 行数）
  - `counts / warnings / errors`
- 入库报告根（`load/techfin_load_to_db.py`）使用**独立序号**，不与爬虫运行目录混放。

## 4. 关键语义

- `level3_code` 是 join 键；中文名只是显示名。
- `region_from`：`text/title/summary/body/scope_city/scope_province/scope_national/aggregate/query/none`。
  loader 默认拒绝县级目标上的 `query/none/scope_national`。
- `aggregation_type`：`total/subset/breakdown/aggregate`。只有 `total` 参与主值；
  `breakdown` 默认拒绝，`subset` 当前未单独拦截。
- `stat_year_src` + `year_confidence`：`period/text/relative/llm/window/doc`；
  `year_confidence < 0.5` 不产主值，loader 默认拒绝。
- `evidence_verified`：LLM 点的证据片段能否在正文/附件中定位；`0` 默认拒绝。
- 金额/数量单位不做跨单位换算；`value_text` 保留原文。

## 5. 旧数据

- 不自动迁移、不自动读写旧根；旧目录只读保留。
- 需要旧数据时：`--input-dir techfin_common_output/<run>`（loader）或
  `--output-dir techfin_common_output`（显式切换，会在旧根继续累积，通常不建议）。
- 新数据根从零开始累积；切换根后不会自动搬移累积库与正文缓存。

## 6. A/A2、A/A3 指标口径速查

| 主题 | 指标 | metric / measure_code | 抽取层源单位 | 落库标准单位 |
|---|---|---|---|---|
| A/A2 | A201 本外币存款余额 | `amount` | 元/万元/亿元/万亿元 | 亿元 |
| A/A2 | A202 私募/创投机构数量 | `count` | 家/户 | 家 |
| A/A2 | A203 管理资本量 | `amount` | 元/万元/亿元/万亿元 | 亿元 |
| A/A2 | A204 银行网点密度 | `density` | 个/万人 | 个/万人 |
| A/A3 | A301 财政科技拨款占比 | `share` | %/％ | % |
| A/A3 | A302 风险补偿资金池规模 | `amount` | 元/万元/亿元/万亿元 | 万元 |

- **金额换算只在 loader 做**：抽取层保留原文单位（`value_text` 也保留原文），loader
  用 `convert_amount_to_standard()` 统一换算到 `dim_index_measure.standard_unit`。
  不要在抽取层预换算，否则 loader 优先解析 `value_text` 时会双重换算。
- **A202/A203 县域替代口径**：`dim_index.is_county_applicable=0`。县级采集使用
  `topic_config.INDEX_KEYWORDS["A2"]["indicators"][...]["county_queries"]`
  （有限合伙企业/私募基金/实缴规模/认缴出资）。入库默认以 `COUNTY_NOT_APPLICABLE`
  拒绝县级行；如研究设计需要代理值，显式加 `--allow-county-not-applicable`，
  loader 会在 `remark` 标记 `county_replacement=1`。
- **A204 只有 density 口径**：纯“银行网点 X 个”不产点；只有“每万人拥有/网点密度 X 个”
  才按 `个/万人` 入库。
- 幂等键仍为 `(region_code, year, level3_code, measure_code, context_type)`，A1/A2/A3
  的 `level3_code` 不相交，跨主题入库不会互相覆盖。

## 7. B/B1～B/B4 指标口径速查

| 主题 | 指标 | metric / measure_code | 抽取层源单位 | 落库标准单位 |
|---|---|---|---|---|
| B/B1 | B101 科技企业贷款余额 | `amount` | 元/万元/亿元/万亿元 | 亿元 |
| B/B1 | B102 科技企业贷款余额增速 | `growth` | %/％ | % |
| B/B1 | B103 知识产权质押融资额 | `amount` | 元/万元/亿元/万亿元 | 亿元 |
| B/B1 | B104 信用贷款占比 | `share` | %/％ | % |
| B/B2 | B201 VC/PE 投资案例数 | `count` | 起 | 起 |
| B/B2 | B202 VC/PE 投资金额 | `amount` | 元/万元/亿元/万亿元 | 亿元 |
| B/B2 | B203 上市科技企业数量 | `count` | 家 | 家 |
| B/B2 | B204 上市科技企业募资额 | `amount` | 元/万元/亿元/万亿元 | 亿元 |
| B/B3 | B301 科技保险保费收入 | `amount` | 元/万元/亿元/万亿元 | 亿元 |
| B/B3 | B302 创业担保贷款发放额 | `amount` | 元/万元/亿元/万亿元 | 亿元 |
| B/B4 | B401 移动支付交易额 | `amount` | 元/万元/亿元/万亿元 | 亿元 |
| B/B4 | B402 数字普惠金融指数 | `index` | —（只采语料） | 指数值 |
| B/B4 | B403 大数据/AI 风控应用 | `score` | —（只采语料） | 分 |

- **B102 的 growth 口径**：`extract/techfin_extract_points.py::_metric_of()` 在
  `scope.metrics == {"growth"}` 且单位为 `%` 时返回 `growth`；该改动已同步到 A/A1-A3、
  B/B1-B4、C/C1-C3 共 10 份同源脚本。A 侧没有 growth 指标，行为不变。
- **`_adapt_unit()` 已泛化**：不再硬编码 A204，而是按指标的 `metrics == {"density"}`
  判断，把「每万人拥有银行网点 3.2 个」「每万人发明专利拥有量 52.3 件」里的 `个`/`件`
  归一为 `个/万人`/`件/万人`；10 份同源脚本一致。
- **指标级互斥正则**：`INDICATOR_SCOPE` 可带 `reject_pattern`（编译后的正则）；抽取脚本在
  数字前 30 字窗口命中即丢弃。C301/C304 用它拦截「独角兽、瞪羚企业共 X 家」合并口径。
- **B402/B403 只采语料**：不写入 `extract_config.INDICATOR_SCOPE`，不产数据点、不入库；
  但仍保留在 `topic_config.INDEX_KEYWORDS` 中，供清洗层判相关性。
- **县域不适用**：B201-B204、B301、B403 的 `is_county_applicable=0`。县级行默认被
  loader 以 `COUNTY_NOT_APPLICABLE` 拒绝；需要代理值时加 `--allow-county-not-applicable`。
  B2 的县域替代口径已写入 `county_queries`（天使轮/A轮融资、新三板/区域股权交易中心挂牌）。
- **B302 口径**：只认发放额/累计发放/投放，余额与贴息资金被非目标主语拦截。
- 金额换算仍只在 loader 做；抽取层保留原文单位。

## 8. C/C1～C/C3 指标口径速查

| 主题 | 指标 | metric / measure_code | 抽取层源单位 | 落库标准单位 |

| C/C1 | C102 技术合同成交额 | `amount` | 元/万元/亿元/万亿元 | 亿元 |
| C/C1 | C103 每万人发明专利拥有量 | `density` | 件/万人、件（每万人语境下归一） | 件/万人 |
| C/C2 | C201 高新技术产业产值占规上工业产值比重 | `share` | %/％ | % |
| C/C2 | C202 科技服务业增加值 | `amount` | 元/万元/亿元/万亿元 | 亿元 |

- **C301/C304 拆分**：原 C301 是「"独角兽"、"瞪羚"企业数量」合并指标；现 C301 独角兽、
  C304 瞪羚。`db/21_seed_index.sql` 已含 36 条指标、38 条口径；已有库执行
  `db/migrations/20261116_001_add_c304_gazelle.sql`。loader 的 `STOCK_INDICATORS` 已加入 C304。
- **C101 县域不适用**：`is_county_applicable=0`；县级行默认被 loader 以
  `COUNTY_NOT_APPLICABLE` 拒绝，需要代理值时加 `--allow-county-not-applicable`。

- **C202 代理口径**：接受「科学研究和技术服务业增加值」作为官方统计代理；营业收入、
  占比、增速不产 C202 点。
- **C201 严格口径**：本次不接受「高技术制造业增加值占比」代理。
- **C302/C303 growth**：沿用 B102 的 `_metric_of()` 规则（`metrics == {"growth"}` 且单位为 %
  时返回 growth）；营收与利润用非目标主语互斥。
- **C301/C304 合并口径**：「独角兽、瞪羚企业共 X 家」由
  `extract_config.COMBINED_UNICORN_GAZELLE_RE` 拦截，不分配给任一指标。
- 金额换算仍只在 loader 做；抽取层保留原文单位。
